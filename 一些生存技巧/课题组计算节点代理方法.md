集群教程是说连
```
export http_proxy=http://10.36.204.1:3128 1 
export https_proxy=http://10.36.204.1:3128
```
但是这个代理似乎不太行，访问不出去

遂探索
```
#先在计算节点上运行一个这个，相当于通过17890端口建立一个与sn01的链接
ssh -4 -N -o ExitOnForwardFailure=yes -L 127.0.0.1:17890:127.0.0.1:7890 zdhs0200@10.36.204.1

#上面那句运行完会保持无输出，此时再开一个终端连到计算节点
export http_proxy=http://127.0.0.1:17890
export https_proxy=http://127.0.0.1:17890
```

另外，export只能解决某一个终端里面的代理问题，在vscode上访问copilot或者codex的时候仍然慢得像蜗牛，可以通过配置.vscode的代理设置解决
**在 VS Code 的“远程设置”里配置代理**
连接服务器后，按 `Ctrl+Shift+P`，搜索：
```
Preferences: Open Remote Settings (JSON)
```
把下面两项合并到现有 JSON 中：（刚开始有可能就是一个空文件。我的文件路径是~/.vscode-server/data/Machine/settings.json）
```
{
    "http.proxy": "http://127.0.0.1:17890",
    "http.proxySupport": "on"
}
```

如果发现上述操作好像没作用（比如登录codex报错）

可以尝试- 按 **`Ctrl+Shift+P`**， 搜索并选择：
```
Remote-SSH: Kill VS Code Server on Host...
```
选择你正在连接的 SSH 主机。 当前远程连接会断开，再用 VS Code 连接一次，它会自动启动 Server。
