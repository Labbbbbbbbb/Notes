### **个人理解：**
什么工作倾向于用多进程？什么倾向于用多线程？
进程与线程本身的意义都是让CPU能并发地处理多个任务，能利用起多核的CPU，而不用在一个任务阻塞的时候空等待
而进程和线程的本质差别在于对资源管理的边界不同，进程的隔离更加彻底，因为它是资源分配的基本单位，拥有独立的内存空间，因此更适合用来避免某个进程崩溃对另一个进程造成影响。
比如完成一个上传文件并进行格式转换的任务，就可以分成web进程和格式转换两个进程，这就是用多进程去完成这个任务，这样一来加入格式转换因为内存有问题导致程序崩溃时不会影响到web进程的空间。反之如果用多线程来处理这个问题，由于线程之间共享资源空间，一个崩溃就会让整个任务都崩溃。
>[!NOTE] 并发和并行有什么区别？
>**并发：多个任务在同一段时间内交替或重叠推进。**  
  **并行：多个任务在同一时刻实际执行。** (可以这样理解：在通常的广义定义下，并行是一种特殊的并发。)
  假设有两个任务：
  A：处理用户登录。
  B：生成报表。
 **一个 CPU 执行核心，也可以实现并发。**
 CPU 先执行 A 一小段，再执行 B 一小段，然后继续 A。由于切换很快，用户感觉两个任务都在推进。但在某一个具体瞬间，这个核心只执行其中一个任务，因此这属于**并发，没有同时执行这两个任务**。**有多个可用 CPU 执行核心时，可以实现并行。**

还有就是和语言的关系，python作为一个解释型语言，运行CPU密集型任务的时候需要频繁调用python解释器，如果是用python写的，这种任务就应该用多进程，因为多进程才有独立的解释器，以免多核计算之间收到GIL限制。

>[!NOTE]
>如果任务是图片压缩、复杂计算，CPU 会长时间忙于计算，而不是等待 I/O。
  在常规启用 GIL 的 CPython 中，多个线程通常不能同时执行 Python 字节码，因此纯 Python 的 CPU 密集任务常采用多进程，让多个进程分别在不同 CPU 核心上计算。
  但这不是所有语言都存在的限制：**Java、C++ 等语言的多个线程本身也能利用多核，因此“利用多核”不等于“必须多进程”。**

和协程的区别：
**协程**：在线程内部运行、由程序或语言运行时调度的执行单元。
它是运行在线程上的一个个任务，可以暂停和恢复，有点像一个微缩版的线程，但是线程中协程的协作方式往往是靠代码主动去await等来实现并发，而线程协作是靠操作系统来抢占，让就绪态高优先级的线程去拿cpu

### 常用命令
#### ps
```
ps -eLf 列出当前时刻的进程快照，-f代表使用完整字段信息
```
输出类似：
```
UID    PID   PPID   LWP  C  NLWP  STIME TTY      TIME CMD
app   1234      1  1234  0     3  10:00 ?    00:00:01 ./server
app   1234      1  1235  0     3  10:00 ?    00:00:02 ./server
app   1234      1  1236  0     3  10:00 ?    00:00:00 ./server
```

| 字段     | 含义            | 上面的例子              |
| ------ | ------------- | ------------------ |
| `PID`  | 线程所属进程的 ID    | 三行都属于进程 1234       |
| `PPID` | 父进程 ID        | 父进程为 1             |
| `LWP`  | 线程 ID，也常称 TID | 分别为 1234、1235、1236 |
| `NLWP` | 该进程的线程总数      | 这个进程共有 3 个线程       |
| `TIME` | 累计消耗的 CPU 时间  | 不是从启动到现在的实际时长      |
| `CMD`  | 程序及启动参数       | `./server`         |

### 查看文件和日志
#### `cat`
参数就是查看的目标文件，一次性输出整个文件，适合小文件。
#### `less`
分页查看文件，适合大文件和历史日志。
#### `tail`
查看文件末尾，或持续追踪新增日志。
```
tail -n 100 app.log 查看log的最后100行
tail -f app.log 先显示末尾内容，再持续显示新增内容。适合一边操作服务，一边观察日志。按 `Ctrl+C` 退出。
```
#### `grep`
**筛选包含指定内容的行。**
```
grep -n 'ERROR' app.log  #查找包含 `ERROR` 的行，并显示行号。

grep -i 'error' app.log  #-i忽略大小写。

grep -n -C 5 'Connection refused' app.log #-C显示匹配行以及前后各 5 行，便于查看错误上下文。
```
其中筛选内容还可以表示为'ERROR|WARN'，| 代表或

| 参数     | 含义           |
| ------ | ------------ |
| `-A 5` | 显示匹配行后 5 行   |
| `-B 5` | 显示匹配行前 5 行   |
| `-C 5` | 显示前后各 5 行    |
| `-v`   | 反向筛选，保留不匹配的行 |
| `-c`   | 统计匹配的行数      |
| `-r`   | 递归搜索目录       |
| `-E`   | 使用扩展正则表达式    |
| `-F`   | 把搜索内容作为普通字符串 |
实时看错误日志可以组合：
```
tail -F app.log | grep --line-buffered 'ERROR'
```
`--line-buffered` 让 `grep` 尽量逐行输出，减少管道中的缓冲延迟。

#### 管道和重定向：组合命令
**管道 `|`：把前一个命令的标准输出，交给后一个命令作为输入。**
```
grep 'ERROR' app.log | wc -l
```
先筛出错误行，再用 `wc -l` 统计行数。这个场景也可以直接用：
```
grep -c 'ERROR' app.log
```
其他重定向：

|写法|含义|
|---|---|
|`> result.txt`|将标准输出写入文件，覆盖原内容|
|`>> result.txt`|将标准输出追加到文件|
|`2> error.txt`|将标准错误写入文件|
|`> output.txt 2>&1`|将标准输出和标准错误都写入同一个文件|

## 用户态vs内核态
**内核态和用户态，是 CPU 执行程序时的两种权限状态；root 和普通用户，是操作系统中的两种用户身份。它们都与权限有关，但属于不同层面。**
https://chatgpt.com/s/t_6ae0a6a05f0881919c04190891f2b3d6

通常要读文件、发网络包就需要进入内核态，程序读取操作系统管理的文件，需要通过系统调用，让内核参与。无论是普通文本、图片、Python 代码，还是系统配置文件，都一样，和文件内容是什么没有关系。之所以需要内核，是因为**文件系统、文件访问权限，以及底层存储设备，都由内核统一管理**。即使这个文件是你自己创建的，也需要通过这个管理机制来读取。（从文件中获取数据通常需要内核参与，但拿到数据以后，对数据的每次访问不都需要进入内核态。）

https://chatgpt.com/s/t_6ae0a7a756208191a7a8cd76c86ecb4e
内核态用户态切换和多线程多进程切换的关系：
进程、线程描述的是“程序如何组织和执行”；用户态、内核态描述的是“CPU 当前以什么权限执行代码”。它们是两个不同维度，可以同时存在。**同一进程的不同线程，可以在不同 CPU 核心上分别执行用户代码和内核代码。**

| 对比         | 用户态 ↔ 内核态切换        | 线程切换               |
| ---------- | ------------------ | ------------------ |
| 换了什么       | 执行权限、执行的代码         | 当前运行的线程            |
| 是否仍是原线程    | 通常是                | 不是，从 A 换成 B        |
| 保存状态的目的    | 内核处理完后，回到当前线程的用户代码 | 将来再次调度 A 时，接着执行    |
| 是否切换进程地址空间 | 通常不需要切换到另一个进程的地址空间 | 同进程线程通常不需要；跨进程通常需要 |
从CPU角度看，用户态进入内核态是同一个线程，然后从用户代码保存返回位置等再执行内核服务代码，再回复用户执行状态。两者维度上没有任何冲突。但是往往调用内核的操作频率是由自己发出的指令频率控制的，高并发服务应尽量减少不必要的系统调用，从而减少用户态与内核态切换的开销


## 网络知识
首先确认是只有某个用户访问不了，还是所有用户都访问不了；是整个网站异常，还是某个页面、接口异常，并确认故障发生时间以及最近是否有发布或配置变更。

然后检查域名解析是否正确，服务器网络和服务端口是否可达；
域名解析不正确的话可能就找不到对面的ip，然后链接超时的话有可能是网络问题，比如代理或防火墙等等，服务端口就是说对面的端口没开，可能所有人都访问不了

怀疑是DNS，如果已经知道正确的ip，可以用resolve参数，用域名:正确ip的形式去访问指定ip
检查网络的话可以去ping或者用curl去看HTTP的状态码是不是200

### 网络拓扑结构
![[Pasted image 20261030133626.png|428]]
这是常见示意，实际设备可能合并：例如家里的“无线路由器”，通常同时集成了**路由器、交换机、无线 AP、DHCP 服务和 NAT** 等功能。

**把这些放到一次上网过程中：**

1. 电脑通过网线接入交换机，或通过 Wi-Fi 接入 AP。
2. DHCP 给电脑分配 IP、掩码、默认网关和 DNS。
3. 电脑向 DNS 查询网站地址。
4. 电脑发现网站 IP 不在本地子网，把数据发给默认网关。
5. 网关根据路由表转发，防火墙检查是否允许；私有 IPv4 上网时通常还会做 NAT。
6. 数据经过运营商网络到达网站，响应再沿相应路径返回。

PS. DHCP是一个协议，不是某个硬件

|配置项|作用|示例|
|---|---|---|
|IP 地址|本机在该网络里的地址|`192.168.1.10`|
|子网掩码|判断哪些目标属于本地子网|`255.255.255.0`|
|默认网关|去其他网络时通常交给谁|`192.168.1.1`|
|DNS 服务器|向谁查询域名对应的地址|`192.168.1.1`|
|租期|这套地址分配可以使用多久|例如 24 小时|
关于家用路由器的功能：

|你在使用的功能|盒子里负责它的部分|
|---|---|
|手机搜索到无线网络、输入密码连接|**无线 AP**|
|多台电脑插网线连接 LAN 口|**交换机**|
|内网与外部网络之间转发数据|**路由功能**|
|自动给设备分配 IP 等配置|**DHCP 服务**|
|多台设备共享公网 IPv4 上网|**NAT/PAT 功能**|
- **宽带/运营商接入**：把你家的网络连接到互联网。
- **路由器**：连接不同 IP 网络。
- **无线 AP**：提供 Wi-Fi 接入。
- **Wi-Fi**：设备使用的无线连接技术。

- **交换机 ≈ 有线网络的多口拓展坞**：让多台有线设备接入同一个网络。
- **AP ≈ 把有线网络扩展给无线设备的接入点**：手机、笔记本通过 Wi-Fi 接入，再由 AP 连到有线网络。

补充两点，避免误解：
1. **交换机不是简单地把一根网线的信号复制到所有接口。** 它会学习设备的 MAC 地址，通常把数据发往对应端口。
2. **AP 也不只是转换插头。** 它还负责无线设备的连接、身份验证、无线加密，以及协调无线通信。
> **交换机和 AP 主要解决“设备怎么接入这个网络”；路由器主要解决“这个网络怎么与其他网络通信”。**

### 概念暂存
子网：一个子网由“网络地址 + 子网掩码（或前缀长度）”确定；一台设备属于哪个子网，则由它的“IP 地址 + 子网掩码”算出来。例如：
```
IP 地址：  192.168.10.25
子网掩码：255.255.255.0，也写作 /24 （255是8位，前三个是255，就是24位）
```
`/24` 表示 IPv4 的 32 位中，**前 24 位是网络部分，后 8 位是主机部分**。这个例子中，前三段确定网络，最后一段区分设备。

|项目|结果|
|---|---|
|子网（网段）|`192.168.10.0/24`|
|网络地址|`192.168.10.0`|
|常规可分配主机地址|`192.168.10.1`～`192.168.10.254`|
|广播地址|`192.168.10.255`|

VLAN：“虚拟局域网”（Virtual LAN），可以把一套交换机网络，在逻辑上分成多个彼此独立的二层网络。
